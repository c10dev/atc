# 일 따라가기 (FOLLOW 탭)

여러 이슈로 나눠 맡긴 일이 있을 때 "지금 어디까지 갔나"를 매번 묻지 않고 **한 화면에서 보는** 방법입니다. 상위 이슈(예: GLOBE의 ATC-253) 하나를 따라가기로 하면, 그 하위 이슈마다 한 줄이 생기고 Todo에서 배포까지의 단계가 점으로 보입니다. 거의 보기만 합니다. 배정하거나 보내는 버튼은 없고, 쓰는 버튼은 `Todo로` 하나뿐입니다(아래 "다음 할 일").

## 따라가기 시작과 끝

- **FOLLOW 탭**(`#follow`, RADAR 바로 옆) 위쪽 입력칸에 상위 이슈 key(`ATC-253`)를 넣고 `따라가기`를 누릅니다.
- 또는 하위 이슈가 있는 이슈의 **FLIGHT 서랍**에서 `FOLLOW` 버튼을 누릅니다. 따라가는 중이면 `FOLLOWING ✓`로 바뀌고, 다시 누르면 끝납니다.
- 번들 오른쪽 아래 `따라가기 끝내기`로도 끝낼 수 있습니다.
- 따라가는 목록은 서버가 `follow.json`(상태 폴더)에 적어 둡니다. 읽는 Linear 팀의 이슈 key만 받습니다. 하위 이슈가 없는 이슈 하나도 따라갈 수 있습니다(줄 하나짜리 번들).

## 한 줄 읽기

한 줄은 이슈 하나입니다: `FLIGHT 번호 · 제목 · Linear 상태`, 단계 점, 지금 글.

번들에 들어오는 이슈는 상위 이슈의 하위 이슈와, 상위 이슈에 **related**로 걸린 이슈입니다. 막는 이슈(blocked by)가 앞에 오고, 같은 층은 key 순입니다.

| 점 | 닿았다는 뜻 |
|---|---|
| `TODO` | Linear 상태가 Todo 이후 |
| `PROP` | DISPATCH가 제안을 만들었다 |
| `APPR` | 승인됨(SUPERVISOR나 모드가) |
| `SENT` | FLIGHT PLAN을 보냈다 |
| `RB` | CAPTAIN이 READBACK했다 |
| `PR` | PR이 열렸다 |
| `CLR` | PR이 CLEARED TO LAND가 됐다 |
| `ON` | 머지됐다(착륙) |
| `IN` | RTS로 서비스에 들어갔다(배포) |

- 초록 점은 닿은 단계, 주황 점은 지금 단계, 속이 빈 점은 아직입니다. `—`는 그 FLIGHT에 없는 단계입니다: STAND 없는 FLIGHT(SURVEY·CHECK)는 PR 이후가 없고 ARRIVED에서 끝나며, `tail:`로 직접 맡긴 FLIGHT는 제안 단계가 없고, MCC AIRPORT가 아닌 곳은 배포(IN)가 없어 착륙(ON)에서 끝납니다.
- 점에 마우스를 올리면 그 단계의 시각이 보입니다. 줄 아래 `기록 n`을 열면 단계 시각과 RECALL·UNABLE·SUPERSEDED 같은 되돌림이 시간 순으로 나옵니다. 되돌려진 줄은 Todo로 돌아가고 기록에는 남습니다.
- 좁은 화면에서는 점 대신 `단계 4/9`처럼 숫자와 지금 글만 보입니다.

## 지금 글

점이 못 알려 주는 "지금 무엇을 기다리나"를 한 줄로 적습니다. 보통 이런 글이 나옵니다.

| 글 | 뜻 |
|---|---|
| `ATC-255 대기` | Backlog인데 막는 이슈가 아직 안 끝남 |
| `풀 수 있음` | Backlog이고 막는 이슈가 모두 끝남(Todo로 옮기면 됨) |
| `우선순위 없음` · `HOLD — …` · `AIRCRAFT 없음 (…)` · 진행 중인 제안 | Todo인데 DISPATCH가 아직 배정하지 않은 이유 |
| `승인 대기` | 제안이 SUPERVISOR의 승인을 기다림 |
| `승인 7분 · 발송 없음` | 승인했는데 FLIGHT PLAN이 아직 안 나감 |
| `발송 4분 · READBACK 대기` | 보냈고 답을 기다림 |
| `작업 42분 · 보통 30분–1시간 30분` | 일하는 중. 보통 걸리는 범위와 견줄 뿐 퍼센트나 도착 예정은 없음 |
| `PR #10 checks-pending · GO AROUND C-0255 READBACK 03:15Z` | PR이 착륙하지 못하는 이유(막힘 코드)와 GO AROUND |
| `착륙 대기` | CLEARED인데 아직 머지 전 |
| `RTS 대기 · 03:50Z 착륙` | 머지됐는데 아직 배포 전 |
| `03:22Z 배포` | 끝 |

`승인했는데 발송 없음`과 `머지했는데 배포 전`은 다른 화면에서는 안 보이던 사이 구간입니다. FLIGHT FOLLOWING이 이미 찾는 문제(`no-pr`, `pr-not-cleared`, `undelivered` …)는 같은 이름의 작은 칩으로 줄에 붙고, 마우스를 올리면 같은 글이 보입니다.

Linear가 최근 45일 안에 바뀐 이슈만 읽기 때문에 오래된 이슈는 `Linear에서 못 읽음`으로 나옵니다. 상태를 짐작해서 그리지 않습니다.

## 막힘

기다리는 시간이 한도를 넘은 줄은 **주황 점**과 `막힘` 표시가 붙고 번들 맨 위로 올라옵니다(나머지는 원래 순서). 번들 제목줄에도 `막힘 n`이 나옵니다. 점에 마우스를 올리거나 글에 마우스를 올리면 이유가 보입니다.

| 어디서 | 한도 |
|---|---|
| Todo, 우선순위가 있는데 제안이 없음 | 30분(HOLD·`tail:` 지정은 일부러 기다리는 것이라 제외) |
| 승인했는데 발송 없음 | 10분 |
| 보냈는데 READBACK 없음, 전달 실패 | 10분 / 바로 |
| READBACK 뒤 PR 없음, PR이 CLEARED가 안 됨, CLEARED인데 착륙 안 함 | FLIGHT FOLLOWING의 기존 한도 |
| 착륙(ON)했는데 배포(IN) 없음(MCC AIRPORT) | 15분 |

## 다음 할 일

줄에 칩이 하나 붙으면 지금 SUPERVISOR가 할 일이 있다는 뜻입니다. 한 줄에 최대 하나이고 아래 순서로 처음 맞는 것이 나옵니다.

| 칩 | 언제 | 누르면 |
|---|---|---|
| `Todo로` | Backlog이고 막는 이슈가 모두 끝남 | **Linear 상태를 Backlog → Todo로 바꿉니다.** FLIGHT 서랍의 상태 버튼과 같은 길이고, 한 번에 한 줄이며 일괄은 없습니다. 그새 상태가 바뀌었으면 서버가 거절하고 그 글이 줄 아래에 나옵니다 |
| `우선순위 정하기` | Todo인데 우선순위가 없어 DISPATCH가 배정하지 않음 | FLIGHT 서랍을 엽니다(Linear에서 정합니다) |
| `승인하러 D-0012` | 제안이 SUPERVISOR의 승인을 기다림 | DISPATCH 탭으로 갑니다 |
| `HUMAN CHECK #n` · `머지 #n` | 사람의 확인이 남은 PR, 또는 CLEARED인데 SUPERVISOR가 머지할 PR(`user` 등급) | PR 서랍을 엽니다 |
| `살펴보기` | 발송·READBACK 단계나 착륙 뒤 배포 단계에서 막힘 | 발송·READBACK은 RADIO, 착륙 뒤는 STRIPS로 갑니다 |

화면 맨 위 `NEXT n`은 따라가는 모든 번들의 칩 개수이고, 누르면 FOLLOW 탭으로 갑니다. 0이면 보이지 않습니다.

## 끝난 번들

모든 줄이 끝나면(Done이고 배포까지 갔거나 배포 단계가 없음, 또는 Canceled) 번들 제목줄에 `완료`가 붙습니다. 하루가 지나면 접힌 채로 남고, 제목줄을 누르면 펼쳐집니다.
