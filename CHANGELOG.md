## [Unreleased]

### Security
- The TOWER, OCC and CROSSCHECK Bash guard (`controller/guard.mjs`) let `jq` through with any arguments, so a control session could read any file or its environment. The same held for the filter of gh's built-in `--jq`. CROSSCHECK runs on external providers, so a secret read this way would leave the machine. Reported by structure.
  - Paths that worked: `jq -R . /home/c10/projects/atc/.env.local` (the Linear API key), `jq . ~/.local/state/atc/fleet.json`, `--rawfile`, `-f`, `jq -n env` / `'$ENV'`, `gh pr view … --jq '$ENV.X'`, and, even on stdin alone, `import "data" as $d {search: "/any/dir"}`, which loads `/any/dir/data.json`.
  - jq now only filters the output of an earlier command. It may not be the first command, and it takes at most one positional argument (the filter).
  - Its options are an allowlist: output formatting, `--arg`, `--argjson` and `--indent`. Everything else is blocked, including `-f`/`--from-file`, `--rawfile`, `--slurpfile`, `-L`, `--args` and `--jsonargs`.
  - The filter may not contain `env`, `$ENV`, `import`, `include`, `modulemeta` or `get_search_list`. gh's `--jq`/`-q` value gets the same filter check, and `-q` clustered with other short flags is blocked.
  - The TOWER, OCC and CROSSCHECK manuals say jq only goes after a pipe.
- The TOWER and OCC Bash guard (`controller/guard.mjs`) let command substitution through inside double quotes: `node atcctl.mjs brief -- "$(touch /tmp/x)"` passed, and so did a backtick. The shell runs these before the command, so a control session could run arbitrary commands. Command substitution and variable expansion (`$(…)`, backticks, `${…}`, `$VAR`) are now blocked anywhere outside single quotes; single-quoted and backslash-escaped text is still allowed. Reported by TEAM_H.

### Changed
- DIRECT briefs carry the issue text as written (ATC-58, [docs/dispatch.md](docs/dispatch.md) "DIRECT briefs"). `directSectionsOf` (FLIGHT PLAN and `GET /api/dispatch/flight/:key/brief`) now removes Linear's backslash escapes (the F7 brief showed `\~31 K`) and turns links to `linear.app/<workspace>/issue/<KEY>/…` into the bare key (`ATC-46`), which cost about 100 of the goal's 600 characters each; a link with its own text keeps it (`the design (ATC-46)`), and other links are unchanged. Code spans and fenced blocks are never altered. A one-line field that is a list item now starts on its own line (`이 작업만의 제약:` then `* Display only.`). The 600-character goal limit counts the cleaned text; `GOAL_MAX`, `BRIEF_BODY_MAX`, the fixed lines and the section rules are unchanged.
- The ad hoc `structure` session is split by role (GitHub #121). Design docs, Linear issues (work orders, EO) and splitting large issues belong to **ENGINEERING**, a working session opened when needed (root `CLAUDE.md` "ENGINEERING", `docs/naming.md` "Working sessions"). ENGINEERING doesn't merge, deploy or message teams, and it and the user are the ones who write to Linear. Landing and deploying `auto`/`flagged` atc PRs is the user's until MCC is in `land` mode, then MCC's (`docs/mcc.md` 8.1). Team sessions now report to ENGINEERING (`atc-task` skill). The AIRCRAFT health next steps, the TOWER manual and the FLEET docs say "whoever sent the prompt (OCC, the user)" instead of structure. MCC is listed with the control sessions. Old records keep `by: "structure"`.
- DIRECT briefs no longer clip exit criteria or constraints (ATC-35, [docs/dispatch.md](docs/dispatch.md) "DIRECT briefs"). Only the goal is cut at 600 characters. On 2026-09-28 the ATC-34 brief lost its `merge` exclusion list after the first item. If goal, exit criteria and constraints together pass 4,000 characters, the FLIGHT PLAN and assignment text keep the goal and say "완료 기준·제약 전문은 이슈 본문에서 읽으세요." instead of carrying a partial list. The ATC-34 body is a test fixture.
- DIRECT briefs (ATC-32, [docs/dispatch.md](docs/dispatch.md) "DIRECT briefs"). atc now hands work to teams with only the goal, the exit criteria, the constraints specific to the task and "finish it in one pass"; standing rules stay in CLAUDE.md, AGENTS.md, guards and branch protection, none of which changed.
  - FLIGHT PLAN: a `BRIEF: DIRECT` line, then 목표, 완료 기준 and 이 작업만의 제약 taken from the issue body (read from Linear at `dispatch release`), a PILOT'S DISCRETION line, the READBACK request, and "끝까지 진행하고, SUPERVISOR 결정이 필요한 것만 멈춰서 물어 주세요." Without Linear the fields are left out.
  - `GET /api/dispatch/flight/:key/brief?to=TEAM_X` gives the same text for assignments by structure or a person.
  - OCC NEW drafts need only 목표 and 완료 기준 (Goal / Outcome, Acceptance / Done criteria / Done when / Exit criteria), each with content; a plain `목표: …` label counts. `rating:SEC` needs a `Hard constraints` line instead of the full Codex Engineering Task sections. The OCC and CROSSCHECK manuals follow.
  - The `atc-task` skill uses PILOT'S DISCRETION: on ordinary ambiguity pick a reasonable default, note it in the PR and keep going; ask first only for guards, record formats or other SUPERVISOR decisions.
- Reviews carry across main-only merges (ATC-31, [docs/occ.md](docs/occ.md) 9.6). vocado's `strict` rule puts every other PR `behind` after each merge; merging `origin/main` moved the head and dropped the review (#394: a DeepSeek pass at 18700c1, then c12b706 — a main merge with the same change — waited for a re-review).
  - For a PR with no review on its head, atc walks back through its commits while each is a merge whose other parents are in the default branch, and keeps the earlier commits `R` whose own change (`compare(main...R)` vs `compare(main...head)`: files, status, blob SHA) equals the head's. Read-only GitHub API; `strict` stays.
  - A human `APPROVED` on `R`, a Codex 👍 after `R`, or a DeepSeek pass on `R` (not for excluded PRs; Muse doesn't carry) clears the review condition; findings on `R` stay `review-findings`. Carried PRs skip the REVIEW queue. `PullRequest.carried` / `landingQueue[].carried`, strip "REVIEW: … (carried from R, main merge only)", `landing.cleared` `carriedFrom`.
- A switch lets the DeepSeek landing reviewer take security PRs when Codex is unavailable (ATC-30, [docs/occ.md](docs/occ.md) 9.5). Codex's 5-hour limit left vocado #392 and #395 with no reviewer.
  - `dispatch.json` `externalReview.security`: `"exclude"` (default, today's behavior) or `"deepseek"`, on the settings window's AGENTS tab (REVIEW row) with the warning "보안 PR diff와 Linear 이슈 본문이 DeepSeek로 나감" (`PUT /api/settings {reviewSecurity}`).

  - **New control folder `review/`** (tmux `atc-review`, `ocx claude` on `claude-ocx-opencode-go--deepseek-v4.1-flash`): Korean `CLAUDE.md` and `/tick` with en translations, `README` (en/ko) with the launch command, fail-closed `.claude/settings.json`, and a `read-guard.mjs` that reuses CROSSCHECK's rule with `review/` as the root. ## [0.1.0] — 2026-09-26

First release. ✈️ Ready for takeoff.

### Added

#### Radar and screens
- RADAR: session ─ worktree ─ ticket columns joined by lines, highlighting worktrees with no owner and in-progress tickets with no worktree.
- FLIGHT STRIPS: one strip per session with status, STANDs held, tickets and CLEARANCEs.
- FIDS: a DEPARTURES board, as a list or a board by flight phase, with split-flap characters.
- AIRPORTS: repository registry with auto-discovery under `~/projects`, 4-letter codes, identity by first commit hash, and open / close / rename / delete.
- OUTSTATION: sessions holding a STAND outside their home AIRPORT.
- Aviation terms and phonetic callsigns throughout (`TEAM_A` → `ALPHA`).
- A scrolling ALERT ticker.
- Themes: Radar Console, Glass Cockpit and Night Sky.
- A settings panel: motion, clock (UTC / local), density (comfortable / compact), FIDS view and range.

#### Claims, handoffs and conflicts
- Claim hook (`hooks/claim.mjs`): a Claude Code `PostToolUse` hook that records which linked worktree each session works in. It counts edited files and `cd` / `git -C` in command position only. Echo strings, heredocs and read-only commands don't count.
- ESTIMATED TRACK: claims inferred from transcript tool calls when there is no hook record.
- Codex sessions, claimed by their cwd.
- Verdicts from claim intervals: HANDOFF, LOSS OF SEPARATION or brief visit.
- Alerts: LOSS OF SEPARATION, NORDO STAND, UNIDENTIFIED, NO CONTACT.

#### Stage 1 — CONTROLLER (TOWER)
- A guarded Claude session in `controller/` that reads a traffic brief and sends CLEARANCEs (TRAFFIC, HOLD, CONTINUE, LAND, REPORT, INFO) to team sessions.
- READBACK tracking on the flight strips.
- `atcctl` CLI and a Bash guard.

#### Stage 1.5 — FLIGHT RECORDER and METRICS
- An append-only daily log of events and 5-minute traffic samples, kept for 30 days.
- METRICS tab: conflicts, CLEARANCE READBACK rate and time, merge wait, and the stage 2 readiness check.

#### Stage 2a — DISPATCH (shadow operation)
- Assignment proposals: which FLIGHT (ticket) goes to which AIRCRAFT (team session), with per-factor scores and slots.
- RELEASE suggestions for neglected work.
- A guarded DISPATCH session in `dispatch/` that reviews proposals and adds notes and CAUTION.
- DISPATCH tab where the SUPERVISOR marks agree or disagree. Nothing is sent to anyone yet.

#### Operations and docs
- systemd user service (`deploy/atc.service`).
- English and Korean docs for the root README and every folder.
