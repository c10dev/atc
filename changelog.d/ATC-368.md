### Added
- Migration rehearsal: for an AIRPORT with a hosted database, the AUTOLAND cycle applies a PR's new migrations to a test database first and, if that passes, checks for an existing restore point (PITR or a recent backup; atc creates none) and applies them to the live database before the PR merges (ATC-368, [docs/dispatch.md](docs/dispatch.md)).
  - Order: declaration check against the K1 effect declared at release, rehearsal, restore point, live apply, post-apply check. The first failure stops the run and live stays untouched (or `live-changed` with the restore point recorded). Steps are recorded in `migrations.jsonl`.
  - One switch per AIRPORT, changed only from the settings window (MIGRATE block, `fromThisApp`; no `atcctl` command). It needs a test database (`hostedDb.testProjectRef`) and the SUPERVISOR's `SUPABASE_MIGRATE_TOKEN`, which is never printed, logged or sent. Off by default.
