### Added
- SUPERVISOR-only writes need a credential that only the SUPERVISOR's own screen holds (ATC-373, [docs/autonomy.md](docs/autonomy.md)).
  - A localhost `Origin` header no longer opens them: any process on the host can write one. The screen keeps a random secret in the browser's storage and sends it as `X-ATC-Supervisor`; the server only knows the sha256 hash, kept in a root-owned `/etc/atc/supervisor.sha256`. A missing, empty or user-writable file refuses every such write.
  - The gate runs before every route and covers all `POST`, `PUT`, `PATCH` and `DELETE` under `/api/` except the writes agents make through `atcctl` and SQUELCH (an allow list, checked against `controller/atcctl.mjs` by a test). That brings DISPATCH approve and reject, RECALL creation, the DISPATCH and SCHEDULE mode switches and every ATFM route under it.
  - A bar on the screen pairs a new device: it shows one `sudo` command with the hash to run once on the host. `GET /api/supervisor/auth` says whether this device is accepted.
