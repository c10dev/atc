### Added
- SERVER SEND (ATC-562, [docs/occ.ko.md](docs/occ.ko.md) 8.5, [docs/dispatch.ko.md](docs/dispatch.ko.md), [docs/fleet.ko.md](docs/fleet.ko.md)): 서버가 OCC의 턴 없이 FLIGHT PLAN을 AIRCRAFT의 background 세션에 직접 보낸다. 승인된 카드의 첫 FLIGHT PLAN을 보낸다. READBACK 없이 10분이 지나면 한 번 다시 보낸다. 닿지 않은 FLIGHT PLAN은 AIRCRAFT에 살아 있는 세션이 다시 생기면 한 번 더 보낸다. 두 번째 실패는 OCC에게 돌아간다.
  - **검사 하나, 호출자 둘.** 서버의 발송은 모두 OCC send-guard와 같은 검사를 같은 코드로 거친다. 검사는 `occ/send-guard.mjs`에서 `server/send-checks.ts`로 옮겼고 둘 다 이것을 가져다 쓴다. guard는 전에 막던 것을 모두 막고, FRESH START나 서버가 이미 보낸 FLIGHT PLAN도 더 막는다. 세션에 쓰는 함수는 검사가 내놓은 것만 받으므로, 검사를 건너뛰는 길은 컴파일되지 않는다.
  - **전달.** Claude Code 세션의 메시징 소켓으로 보낸다. 서버는 보낼 때 살아 있는 세션 id로 받는 세션을 정하고, 저장된 글을 그대로 쓴다. 세션에는 "ATC"가 보낸 메시지로 보인다. CAPTAIN은 여전히 이름으로 OCC에 답하고, OCC가 READBACK을 전처럼 기록한다. 쓸 때마다 받는 세션의 대화 기록에서 확인한다. 10분 안에 보이지 않으면 서버는 발송을 멈추고 모든 FLIGHT PLAN을 OCC에게 돌린다.
  - **두 번 보내지 않음.** 서버가 보낸 카드(`sentVia: "server"`)와 서버가 곧 보낼 승인된 카드에는 `dispatch release`가 409를 준다. 서버 job이 3분 동안 돌지 않았으면 OCC가 전처럼 보낸다.
  - **스위치와 세는 수.** 설정 창 AUTOMATION → OPERATIONS → SERVER SEND에 스위치 셋(`first`, `resend`, `retry`)이 있다. SUPERVISOR 전용, 기본 on, shadow 없음. 블록은 날마다 센다: 보냄, 잘못 보냄(기대 0), 두 번 보냄, 검사가 막음(사유별), 실패, 안 보임, OCC에게 넘김. 보낼 때마다 FLIGHT RECORDER에 `server-send` 줄이 남고, 그 줄에 제안 id, 저장된 글의 해시, 세션 id, 검사 결과가 실린다.
