### Added
- FOLLOW tab (ATC-276, [docs/follow.md](docs/follow.md) "F1 as built"): follow a parent issue and see each sub-issue's stage from Todo to deployed, including approved-not-sent and landed-not-deployed, in one place.
  - `#follow` sits right after RADAR. One block per followed bundle (the parent's children plus issues related to it, ordered by blocker chain, then key), one row per issue with stage dots (`todo`, `proposed`, `approved`, `sent`, `readback`, `pr`, `ci`, `landed`, `deployed`), a "now" line and an expandable history. Stages that do not exist for a FLIGHT show `—` (STAND-free FLIGHTs end at ARRIVED, `tail:` FLIGHTs start at `pr`, deployed exists only for the MCC AIRPORT). RECALL, UNABLE and SUPERSEDED reset the row to `todo` and stay in its history.
  - The pure `followBoardOf` (`server/follow.ts`) adds no new facts: it joins the snapshot, proposals, OOOI milestones, the DISPATCH plan and FLIGHT FOLLOWING (`readback` to `arrived` and the issue codes are read from `followingOf`, not computed again). `GET /api/follow` is read-only and calls neither GitHub nor Linear.
  - The followed list is a setting, `follow.json` in the state folder, changed with `POST /api/follow {parent, on}` (this app only, Linear team keys only, atomic write; no JSONL, grants nothing). The FLIGHT drawer shows a `FOLLOW` / `FOLLOWING ✓` toggle on issues with children.
  - Guide page "일 따라가기" in the DOCS tab and a FOLLOW row in the screens guide.
