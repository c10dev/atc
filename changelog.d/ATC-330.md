### Changed
- AUTOLAND GROUND STOP latches when `applicationCheck` names a workflow, not only a check run (ATC-330, [docs/occ.md](docs/occ.md) 9.7).
  - Before, the value had to equal a check-run name on `main`'s head; a value that named the workflow that runs the check never matched, so GROUND STOP never latched. Now a failing check run whose workflow has that name latches too (exact match, case ignored; the check-run-name match is unchanged, and `autoland.json` stays one string). The workflow of each check run is read with one read-only Actions runs call per new `main` head (one more only when a new check suite appears on the same head); if the call fails, check-run names decide as before.
  - A configured name that matches no check run and no workflow on `main`'s head now shows a warning row under AUTOLAND in the settings window and in `autoland.applicationCheckWarnings` of `GET /api/settings` (memory only), instead of silently never latching.
