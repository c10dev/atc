### Changed
- RELEASE shows the order to fire: a tree per parent issue (header `끝남 24/43` and `다음 발권: ATC-n`), each issue under the issue that blocks it, with a state word (`READY`, `Todo`, `대기: ATC-n`, or a flight stage) and the 발권 button where firing is possible today. Finished issues fold into the group's count. The fireable rows are ordered by priority, then how many issues firing them unblocks (DISPATCH's `unblock` count), then the oldest wait. A work order's `Sequence: after ATC-n — <reason>` line in `## Release` places the row after ATC-n and shows `after ATC-n: <reason>` without blocking it; a row that shares files with a flying or earlier-ordered issue shows `같은 파일: ATC-n` (from DISPATCH's overlap data). `GET /api/releases` gains `tree`; the existing lists stay. The work-order format rules (`docs/rules.ko.md`, `duty/CLAUDE.md`) describe the `Sequence:` line and when to use it instead of `blockedBy` (ATC-456).
