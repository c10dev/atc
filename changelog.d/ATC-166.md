### Added
- CONTROL RECYCLE (ATC-166, [docs/control-recycle.md](docs/control-recycle.md) 2.4): atc can stop and relaunch a control session (TOWER, MCC, CROSSCHECK) whose context passed its cap, at a safe moment, so the SUPERVISOR no longer does it by hand. The switch is in the settings window, AUTOMATION tab: `off` (default), `shadow` (records "would recycle" in the FLIGHT RECORDER and does nothing), `on` (⚠). It recycles only when the context is over the cap, the job is between turns, the session's safe-moment condition holds (no RTS running or starting; TOWER no un-acked events or overdue CLEARANCE; OCC no unreleased, recalling or fresh FLIGHT PLAN and no open CREW CHANGE, when OCC is turned on), the session was not recycled in the last 3 hours and no other one is being recycled. It uses the FLEET STOP and LAUNCH functions, confirms the job is gone by its saved pid, and launches with the same ACCOUNT.
  - Default caps: TOWER, CROSSCHECK 250k, MCC 150k, REVIEW none; each is editable in the same block, with the current context next to it (`GET /api/control/recycle`).
  - OCC is excluded from automatic recycle until its unrecorded-report gap is closed (SUPERVISOR decision 2026-09-30): `auto: { OCC: false }` in `control-recycle.json`, switchable per session in the settings window. Its context is measured against a 250k cap and, over it, atc raises one SUPERVISOR ALERT (ADVISORY) and does not restart it.
  - One `control` `recycle` line per attempt (context before, reason, result), one `recycle-mode` line per switch change, and a SUPERVISOR ALERT (ADVISORY on success, CAUTION on failure; a failed LAUNCH says the session stays stopped).

### Changed
- MCC's context-cap text: with `recycle.mode` `on` (new in `GET /api/mcc/queue`) MCC no longer asks the SUPERVISOR to STOP and LAUNCH it and is not BLOCKED for it; otherwise it only logs "context <n>k — CAP 초과". The MCC manual also says how a fresh session picks up.
- `deploy/landing-tier.mjs` lists `server/control-recycle-run.ts` as a side-effect file.
