### Changed
- CONTROL WAKE (ATC-557 part a, [docs/control-recycle.md](docs/control-recycle.md) 7, [docs/fleet.md](docs/fleet.md) 8.5.1): TOWER, OCC and MCC no longer run a `/loop`. Each stays an idle background session, and the server wakes it with one message when something needs a decision.
  - **Events.** The server reads the same brief the role's `/tick` reads and lists what `/tick` would act on, one item per thing: new events, second silences, review findings (FIX, INSPECTION), and anything outside the menu. Team replies (UNABLE, questions) still wake the session by name, as before.
  - **One message per new event.** `[ATC WAKE W-0001] TOWER` carries what is new, what is still open, what was resolved since the last wake and the open FLIGHTs it bears on. The session runs `atcctl tick <role> --wake W-0001`, follows `/tick`, and ends with `WAKE RESULT: acted` or `WAKE RESULT: nothing`.
  - **Same writer.** A new check kind in `server/send-checks.ts` mints the same checked-send brand as a FLIGHT PLAN; `deliverChecked` is still the only code that writes to a session socket, and only the production server writes.
  - **Breaker per target kind.** The ATC-562 breaker is now scoped: team FLIGHT PLANs have one, each control role has its own. A busy control session never stops FLIGHT PLAN sends to teams.
  - **Transition.** LAUNCH picks the first message from the switch (`[ATC WAKE BOOT] <ROLE>` or `/loop <n>m /tick`) and records `wake` on the launch line. A session launched in the other mode is relaunched once through the CONTROL RECYCLE path at a safe moment. Until then its `/loop` ticks end at once (`TICK WAKE-MODE`), unless the wake job or the role's breaker has stopped, in which case `/tick` works as before.
  - **Switch and counters.** Settings window, OPERATIONS → CONTROL WAKE: one switch per role (`loop` or `wake`, default `wake`, SUPERVISOR only). The block shows, per role for 7 days, wakes and three misfires: an event with no wake, a wake for work the brief already fully determined, and a wake that found nothing to do. Every wake and its input is a FLIGHT RECORDER `control-wake` line.
  - **Manuals.** `controller/`, `occ/` and `mcc/` CLAUDE.md and their `/tick` skills describe both modes.
