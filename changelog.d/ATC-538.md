### Added
- EVENT LOOP LAG: the server now measures event-loop delay (`perf_hooks.monitorEventLoopDelay`) and writes its p99 and max for each JOB TIMING window into the existing `job-timing/` line (`loop`). When the p99 stays above a threshold (default 250 ms) for N consecutive windows (default 3), a CAUTION alert says the server is slow; a window back under the threshold clears it. Both numbers are in Settings → server. A SUPERVISOR-only switch `EVENT LOOP LAG` (default on, same pattern as `JOB TIMING`) turns the alert off. Alert episodes (`open`/`close`) are recorded, and a MISFIRE (cleared within 10 minutes of being raised) is counted next to the other misfire counters in METRICS → MISFIRE. EFFECT CHECK gains `timing:event-loop-p99` for a work order's `## Measure`. Nothing on any screen changes ([docs/job-timing.md](docs/job-timing.md)).
