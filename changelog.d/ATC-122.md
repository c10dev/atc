### Added
- Response attributes on atc messages (ATC-122, [docs/guide/radio.md](docs/guide/radio.md)), as in CPDLC.
  - Each message's closing line says which answer closes it. Instructions (LAND, HOLD, CONTINUE CLEARANCEs, FLIGHT PLAN, CREW CHANGE) are W/U: `READBACK`, `UNABLE <id> — reason` or `STANDBY <id>`. Notices (INFO, TRAFFIC, REPORT) are R: `ROGER <id>`. RECALL still closes only with `READBACK D-xxxx RECALL`. `READBACK` stays valid for every message.
  - UNABLE closes a CLEARANCE (new `unable` op), a FLIGHT PLAN (as `decline`) or a CREW CHANGE (new `unable` status). The control session doesn't resend; it reports to the SUPERVISOR. FLIGHT FOLLOWING shows an UNABLE with a FLIGHT for a day, and `crew-change brief` lists CREW CHANGE UNABLEs.
  - STANDBY keeps the message open and restarts the 10-minute READBACK overdue once, from the first STANDBY. A second STANDBY is only recorded.
  - atcctl: `roger`, `unable <id> -- <reason>`, `standby` for CLEARANCEs; `dispatch unable|standby`; `crew-change unable|standby`. The server refuses an answer the message can't take (ROGER on W/U, STANDBY on R) with the reason.
  - STRIPS stamps show ROGER, STANDBY and UNABLE with its reason; DISPATCH IN FLIGHT rows show STANDBY; DECLINED reads `DECLINED · UNABLE`. CLEARANCE metrics count an UNABLE as answered.
  - Root `CLAUDE.md`, the `atc-task` skill and the TOWER and OCC manuals list the answers. The suggested READBACK line for other AIRPORTs' `CLAUDE.md` carries them too.
