### Added
- Automatic FRESH START (ATC-560, [docs/fleet.md](docs/fleet.md) 8.6, [docs/dispatch.md](docs/dispatch.md)): when OCC releases an approved ASSIGN and the AIRCRAFT's session already flew a FLIGHT, the server runs the ATC-73 FRESH START itself (STOP, then LAUNCH with the CREW BRIEFING and the FLIGHT PLAN as the first prompt) instead of sending to the old conversation. In atc's own data a session's third or later FLIGHT used about 3 times the tokens of its first for the same number of requests.
  - Per-AIRPORT switch in the settings window, AUTOMATION → OPERATIONS → FRESH START (`fresh-start.json`, SUPERVISOR only): `off` (the button only), `always`, `over` (context above the session's base + 50k, about 100k). It ships `always`: the first server start after deploy writes `always` for every open AIRPORT once. A missing or broken file reads `off`.
  - Not restarted, with the reason recorded, and sent as before: the session's first FLIGHT, an open PR of its own, a STAND of an unfinished FLIGHT, not an idle background session, RESTARTING, NORDO, LIMIT, FUEL hold. Ground stops still refuse, and OCC never sends a restarted card again (`sentVia: "fresh-start"`). While a restart runs, `dispatch release` answers with the existing RESTARTING refusal.
  - Every automatic decision is one FLIGHT RECORDER `dispatch` `fresh-start-auto` line with its input (FLIGHT, AIRCRAFT, context size, base, threshold, switch value, the FLIGHTs already flown).
  - Misfire counters per AIRPORT for the last 7 days under the switch: restarts, skips by reason, failed restarts by stage, and for restarted AIRCRAFT their restarted against non-restarted FLIGHTs (BLOCKED or questions, median tokens per FLIGHT, FIX or GO AROUND).

### Changed
- FRESH START is no longer "never automatic" ([docs/fleet.md](docs/fleet.md) 8.6). The button stays, refuses while a restart for the card is already running, and the approved-card relaunch (ATC-388) leaves such a card alone.
