### Fixed
- An occasional `fetch failed` on a Linear call no longer costs the SUPERVISOR work. Reads and writes retry up to 2 times (about 250 ms, then about 1 s, with jitter; `Retry-After` for 429) on a network-level failure and on HTTP 429, 502, 503 and 504, each attempt with its own 10 s timeout. A retried write never duplicates: an issue or comment is created with a client-chosen id and looked up before it is sent again. The error text names the hop and the cause (`fetch failed (atc server → Linear) [dns ENOTFOUND]`, `(atcctl → atc server)`). Every failed attempt, retry, recovery and give-up is a FLIGHT RECORDER line `linear-call` (no text, no token), counted by hop and cause on METRICS → MISFIRE. The retry count is a SUPERVISOR setting (`linearRetries`, 0 to 3, default 2; 0 is the old behavior). The MCC INSPECTION packet and `duty flight` use the same retried reads ([docs/linear-retry.md](docs/linear-retry.md)) (ATC-561).
