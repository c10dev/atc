### 추가
- DUTY 채팅(DUTY D2, ATC-220, [docs/duty.md](docs/duty.md) "D2 as built"): atc 서버가 DUTY용 `claude -p` stream-json 프로세스 하나를 쥐고, SUPERVISOR가 글 서랍에서 그와 이야기한다. 기본은 꺼짐(`duty.json`의 `duty.enabled`, 설정 → OPERATIONS → DUTY 스위치, 켤 때 ⚠). SUPERVISOR가 켜기 전에는 운영에서 아무것도 돌지 않는다.
  - 런타임(`server/duty-run.ts`, D1이 미리 올려 둔 외부 부작용 파일): 첫 글에서 `dutyArgvOf`와 `cleanEnv(<ACCOUNT 폴더>)`로 띄운다. 프로세스 하나에 입력 큐 하나(둘째 글은 줄을 서고 보낸 쪽은 "DUTY is answering"을 본다). **중단**은 `interrupt` 제어 메시지를 쓰고 프로세스는 그대로다. `duty.idleMin`(기본 30분) 동안 입력이 없으면 stdin을 닫아 끝내고, 다음 글이 `--resume <id>`로 이어 띄운다(`duty-session.json`). **NEW SHIFT**는 다음 글을 새 대화 id로 시작한다. 갑자기 죽으면 마지막 stderr 줄과 함께 `down`이고, 5분에 3번 죽으면 NEW SHIFT까지 `down`에 머문다.
  - 시험이 있는 순수 조각: `duty-stream.ts`(stream-json 줄 → `user`·`text`·`tool`·`state`·`usage` 이벤트. 도구는 이름과 한 줄 요약만, 입력·출력은 싣지 않는다. 모르는 줄은 무시하고 깨진 줄은 센다), `duty-machine.ts`(idle → thinking → idle, 큐, 유휴 종료, 죽음 뒤 재시도 제한).
  - `POST /api/duty/message`(글, 그리고 PNG·JPEG·WebP 그림 한 장 5MB까지), `/api/duty/stop`, `/api/duty/new-shift`는 SUPERVISOR 전용이다(`fromThisApp` Origin 검사, `atcctl`은 DUTY에 글을 보낼 길이 없다). DUTY가 꺼져 있으면 이유와 함께 거절한다. `GET /api/duty/history?before=`는 `duty.jsonl`을 쪽으로 나눠 주고, `GET /api/duty/status`는 상태·ACCOUNT·대화 id 앞자리·컨텍스트·CAP을 준다. `/api/events?topics=duty`가 이벤트를 흘린다(옵트인).
  - `duty.jsonl`·`duty-session.json`·`duty-images/`는 상태 폴더에 있고 저장소에는 없다. 기록은 사용자 글, 완성된 DUTY 글, 도구 이름+요약 줄, 턴 사용량이다.
  - 화면: 헤더의 `● DUTY` readout(켜져 있을 때만, 점이 상태)이 DUTY 서랍을 연다. 주소 `#duty`로 어느 탭 위에서도 열린다. 오른쪽 약 440px, 폰에서는 화면 전체이고 Esc·배경·×·뒤로로 닫는다. 머리줄 `DUTY · acct-2 · context 12/250k`와 확인 단계가 있는 NEW SHIFT, 스트리밍 대화, 작고 흐린 도구 줄, Enter로 보내기·Shift+Enter 줄바꿈·그림 붙여넣기, 답하는 동안의 중단 버튼. 카드와 QUEUE 줄은 D3이고, DUTY의 글은 소리로 읽지 않는다.
  - DOCS 탭에 안내 쪽 "DUTY 채팅".
