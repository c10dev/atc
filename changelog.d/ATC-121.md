### Fixed
- MCC RTS no longer races its own landings (ATC-121, [docs/mcc.md](docs/mcc.md) "RTS race as built"). The main CI atc reports (MCC queue, UPDATE bar, ATFM) is read for one commit: the head SHA is resolved first and its check runs and status are read by that SHA. A new commit whose usual check (`ciCheck`, `check` for ATCC) has not started yet reads as pending, not ok or none. A refused RTS start no longer holds the next one for 5 minutes. `POST /api/mcc/rts` answers not due when the last MCC landing is newer than the main CI state it read.

### Changed
- MCC manual (`mcc/CLAUDE.md`, `/tick`): when `rts.due` is true, run `mcc rts` before landing, and don't run it right after a landing in the same pass (ATC-121).
