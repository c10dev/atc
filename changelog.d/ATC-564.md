### Fixed
- Tests can no longer write to the production state folder. The FLIGHT RECORDER (`server/recorder.ts`) and four other modules (`clearances.ts`, `dispatch.ts`, `landing-review.ts`, `proposals.ts`) fixed their file path from `config.stateDir` at import, so a test that pointed `config.stateDir` at a temporary folder after the import still wrote to `~/.local/state/atc/`; on 2026-10-06 `server/update-run.test.ts` wrote 20 fake `mcc-auto` RTS lines there that way. They now read the path each time, and `config.airportsFile` follows the current `stateDir` unless it is set explicitly.
- A guard (`server/state-guard.ts`): inside `node --test`, reading `config.stateDir` or `config.airportsFile` while it points at the production state folder throws and fails the test file, even if the error is caught. It compares path strings only. 23 test files that reached the production folder now import `./test-hermetic.ts` first.
- The MCC SERVER AUTO numbers and recent lines (settings window, `GET /api/mcc/queue`) skip those 20 fake lines (`rts` lines from `c0ca22e000…` between 2026-10-06 06:59Z and 07:01Z). The recorder file is not edited; the exclusion is to be deleted after retention prunes that day.
