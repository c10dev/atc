### Added
- SERVER SEND (ATC-562, [docs/occ.md](docs/occ.md) 8.5, [docs/dispatch.md](docs/dispatch.md), [docs/fleet.md](docs/fleet.md)): the server delivers FLIGHT PLANs to AIRCRAFT background sessions itself, with no OCC turn. It sends the first FLIGHT PLAN of an approved card. It resends a FLIGHT PLAN once after 10 minutes without a READBACK. It retries once a FLIGHT PLAN that came back undelivered, as soon as the AIRCRAFT has a live session again. A second failure goes back to OCC.
  - **One check, two callers.** Every server send passes the same checks as OCC's send-guard, run by the same code. The checks moved from `occ/send-guard.mjs` to `server/send-checks.ts`, which both import. The guard refuses everything it refused before, plus a FLIGHT PLAN already sent by FRESH START or by the server. The function that writes to a session accepts only the check's output, so a path that skips the check does not compile.
  - **Delivery.** Delivery goes through the session's Claude Code messaging socket. The server resolves the live session id at send time and writes the stored text unchanged; the session sees it as a message from "ATC". The CAPTAIN still replies to OCC by name, and OCC records the READBACK as before. Each write is confirmed in the receiver's transcript. If a write is not seen (10 minutes once the receiver is idle, 60 minutes while it stays busy), the server stops sending and hands every FLIGHT PLAN back to OCC.
  - **No double sends.** `dispatch release` answers 409 for a card the server sent (`sentVia: "server"`) and for an approved card the server is about to send. If the server job has not run for 3 minutes, OCC sends as before.
  - **Switches and counters.** Three switches in the settings window, AUTOMATION → OPERATIONS → SERVER SEND (`first`, `resend`, `retry`; SUPERVISOR only, default on, no shadow). The block counts, per day: delivered, sent wrongly (expected 0), sent twice, refused by the check (with reasons), failed, not seen, and handed back. Every send is a FLIGHT RECORDER `server-send` line with the proposal id, the stored-text hash, the session id and the check result.
