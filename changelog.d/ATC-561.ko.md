### Fixed
- Linear 호출의 가끔 나는 `fetch failed`가 더는 SUPERVISOR의 일을 막지 않는다. 읽기와 쓰기는 네트워크 수준 실패와 HTTP 429·502·503·504에서 두 번까지(약 250 ms, 약 1 s, 지터 포함, 429는 `Retry-After`) 다시 시도하고, 시도마다 10 s 시간 제한이 따로 있다. 다시 보낸 쓰기는 중복되지 않는다: 이슈·댓글은 클라이언트가 고른 id로 만들고 다시 보내기 전에 먼저 찾아본다. 오류 글은 구간과 원인을 적는다(`fetch failed (atc server → Linear) [dns ENOTFOUND]`, `(atcctl → atc server)`). 실패한 시도·다시 시도·복구·포기는 모두 FLIGHT RECORDER의 `linear-call` 줄(글·토큰 없음)로 남고, METRICS → MISFIRE가 구간·원인별로 센다. 다시 시도 횟수는 SUPERVISOR 설정(`linearRetries`, 0~3, 기본 2, 0은 옛 동작)이다. MCC INSPECTION 자료와 `duty flight`도 같은 다시 시도하는 읽기를 쓴다([docs/linear-retry.ko.md](docs/linear-retry.ko.md)) (ATC-561).
