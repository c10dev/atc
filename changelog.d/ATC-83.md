### Changed
- FUEL reads watch the transcripts and keep a disposable cache, so a restart resumes instead of re-reading everything (ATC-83, [docs/fuel.md](docs/fuel.md) 4.1 "Read watch and disposable cache as built").
  - The first `/api/fuel?days=7` after a restart went from 3.8–4.6 s (1.15 GB read) to 0.54 s (0 bytes read); server memory after that call fell from about 430 MB to 336 MB. Measured on a test server with the real transcripts, read-only.
  - `fs.watch` (recursive) on `~/.claude/projects` marks changed transcripts, so the list re-stats only those and changed files are read within about half a second. A full walk every 60 s stays, and a failed watch falls back to the old full walk. FLEET CONTEXT SIZE and the FUEL WATCH brief now refresh 5 s after a transcript changes instead of waiting out 60 s.
  - The cache lives in `~/.cache/atc/fuel/` (not the state directory): one file per transcript with the read position and the fields FUEL already keeps, never transcript bodies. It is versioned and ignored and rebuilt when unreadable, stale or from another format; deleting it costs one cold scan. What FUEL computes is unchanged (a test compares results with and without the cache).
