### Added
- LAUNCH ACCOUNT in the settings window (ATC-239, [docs/accounts.md](docs/accounts.md) 5.4): two dropdowns in ACCOUNTS, one for AIRCRAFT and one for control sessions, pick the ACCOUNT the next LAUNCH uses. It is a default switch, not a bulk edit: every AIRCRAFT's home stays as it is, "각 home (프로필)" restores today's behaviour, and running sessions never move (that stays ACCOUNT CHANGE, approved per AIRCRAFT).
  - New optional `fleet.json` key `launchAccount: {aircraft?, control?}`. A previous build ignores it and keeps it when it rewrites the file (tested). A label that is no longer registered has no effect and shows a warning.
  - LAUNCH order: the ACCOUNT named in the request (LAUNCH panel picker, ACCOUNT CHANGE approve, RESUME, CONTROL RECYCLE) → the LAUNCH ACCOUNT → home → `~/.claude`. The usual refusals (not logged in, FUEL hold, `maxLaunched`) apply to the chosen ACCOUNT; nothing falls back silently.
  - FLEET PLAN: while the AIRCRAFT setting is on, ACCOUNT CHANGE treats it as the effective home (no "way back" to the profile home), and ENTRY and the FUEL check for LAUNCH use it; an ENTRY is blocked with a reason when that ACCOUNT is refused.
  - `PUT /api/fleet/launch-account` is SUPERVISOR only (`fromThisApp`; the page sends `Content-Type: application/json`). The FLEET LAUNCH panel preselects the LAUNCH ACCOUNT and the FLEET header shows `LAUNCH ACCOUNT acct-3` while it is set. Guide page updated.
