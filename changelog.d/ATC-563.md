### Changed
- MCC SERVER AUTO has one lander for `auto`-tier PRs: while the switch is on and the server's `mcc-auto` job is live (it started a pass in the last 3 minutes), the MCC session's `mcc land` refuses an `auto`-tier PR the server would land (`LAND 안 함 — MCC SERVER AUTO on …`). A head the server was refused or failed on is handed over as before; `flagged` and `user` tier, ESCALATEd PRs and mode `rts` are unchanged. The MCC manual now says the session does not land `auto`-tier PRs while the switch is on.

### Fixed
- A merge that lost a race (HTTP 405 "already in progress", or a re-read showing the PR already merged at the same head) is recorded as `already-landed` in `mcc.jsonl` and in the `mcc-auto` FLIGHT RECORDER line, instead of a failed land. It is not counted as refused or as a misfire, and the settings window shows it as its own number. The MCC session's own `mcc land` prints `already landed`. Any other 405 is still `failed`. See [docs/mcc.md](docs/mcc.md) "One lander for auto-tier PRs as built (ATC-563)".
