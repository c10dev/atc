### Added
- DUTY L1 권한(DUTY D7a, ATC-235, [docs/duty.md](docs/duty.md) "D7a as built"): DUTY가 ENGINEERING의 일상 업무를 직접 한다. 자기 `duty-*` STAND에서만 고치고, `claude/duty-*` 브랜치를 커밋·푸시하고, PR을 열고, 서버를 거쳐 Linear에 쓴다. 기본은 꺼짐(`duty.json`의 `l1`). 등급 `user`(DUTY의 설정·guard, 루트 `CLAUDE.md`, `deploy/`).
  - `atcctl duty stand <이름>`·`stand-done <이름>`: 서버가 `.claude/worktrees/duty-<이름>`을 `origin/main`에서 `claude/duty-<이름>` 브랜치로 만들거나 치우고 `node_modules`를 하드링크한다. 이름에 ATC key를 넣지 않는다.
  - guard(fail-closed)는 `Edit`·`Write`를 `duty-*` STAND 안의 `.md` 파일에만 통과시키고, 심볼릭 링크를 푼 경로로 본다(`..`가 든 경로는 거절). STAND 안이어도 자기 권한을 정하는 파일은 쓰지 못한다: `duty/`, `*guard*`, `.claude/`, `.github/`, `package*.json`, `deploy/`, `hooks/`, 루트 `CLAUDE.md`, `.env*`, `.git*`, `node_modules`. git은 STAND 안에서 정해진 형식만(`add`, `commit -m`, `push -u origin claude/duty-*`, `fetch origin`, `merge origin/main`. `--amend`·`--no-verify`·`--force` 없음), `gh pr create`는 `--base main --head claude/duty-*`와 제목이 있을 때만이고 Draft는 없다. `gh pr merge|edit|api`, `curl`, `systemctl`, `kill`, `npm`, `claude`, `SendMessage`는 그대로 막힌다.
  - `atcctl duty linear create|update|comment`: 서버가 자기 키로 Linear ATC 팀에 쓴다(DUTY에는 MCP가 없다). 새 이슈는 우선순위가 필요하고, 상태는 Backlog·Todo까지, 있는 라벨만, 삭제·닫기는 없다. 한 번마다 FLIGHT RECORDER 한 줄(`by: "DUTY"`), 본문은 적지 않는다. `POST /api/duty/stand|stand-done|linear`는 `l1`이 꺼져 있거나 `Origin` 헤더가 있는 요청이면 403이다.
  - 루트 `CLAUDE.md`의 "ENGINEERING"이 "DUTY"로 옮겨 간다(ENGINEERING 세션은 같은 규칙의 break-glass로 남는다). `docs/naming.ko.md`가 DUTY를 L1 관제 세션으로 적고, `duty/CLAUDE.md`가 ENGINEERING의 일과 적용되는 루트 규칙을 갖는다. ADOPT 문구는 SUPERVISOR가 채팅에서 동의한 뒤 설계 초안 PR을 쓰라고 청한다. 가이드 "DUTY 채팅" 쪽을 고쳤다.
