### Added
- Release record: DISPATCH assigns only FLIGHTs the SUPERVISOR has released (ATC-362, [docs/dispatch.md](docs/dispatch.md)).
  - `releases.jsonl` keeps who released each FLIGHT, through which channel (`screen` click, `duty-chat` words, or `attested` words to another session), when, and a hash of the goal, done-when and declared K effects. The server refuses a `screen` release unless it comes from the atc screen.
  - A Todo FLIGHT with no record (or whose body changed after the release) is a proposal: DISPATCH skips it with a visible reason, and the RELEASE panel on the DISPATCH tab releases it with one click.
  - The FLIGHTs already in Todo are released with one bulk confirmation, which turns the gate on (`dispatch.json` `releaseGate`: `auto` default, `on`, `off`).
  - `atcctl release [brief]` reads the record; `atcctl release attest` records a session's attestation, counted per session.
