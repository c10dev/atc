### Changed
- DISPATCH no longer sends a FLIGHT PLAN into nothing (ATC-183, [docs/dispatch.md](docs/dispatch.md) "Undelivered FLIGHT PLANs as built"). `POST /api/dispatch/proposals/:id/release` answers `409` with `AIRCRAFT 세션 없음 — 보내지 않음 (LAUNCH 필요)` when the proposal's AIRCRAFT has no live session, whether or not it is RESTARTING; the approval stays, and a `launch: true` card is exempt.
  - Changed control rule: the OCC manual and tick skill (`occ/CLAUDE.md` / `.en.md`, `flight-plan`, `crew-change`, `SKILL`): when the `SendMessage` result is `success:false`, OCC runs `dispatch undelivered` at once, does not send again in the same tick and does not log "sent".

### Added
- `atcctl dispatch undelivered D-xxxx -- <reason>` (`POST …/undelivered`), for `sent` proposals only: an append-only `undelivered` op returns the proposal to `approved` so the next `dispatch release` tries again, or the next sync closes it as `AIRCRAFT 불가: 전달 실패 — <reason>` when the AIRCRAFT is no longer a candidate. It is not a SUPERVISOR verdict, so the 24-hour pair rule does not start. It raises one CAUTION alert (a FLIGHT FOLLOWING `undelivered` issue naming the proposal, the AIRCRAFT and the reason) and marks the DELIVERY transmission in RADIO (`undelivered`, `closedBy`). No new record file, and `SENT` never depends on reading OCC's transcript.
