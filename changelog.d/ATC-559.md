### Added
- Solo by default (ATC-559, [docs/dispatch.md](docs/dispatch.md) "Solo by default as built"): the FLIGHT PLAN (and the DIRECT assignment text used by FLEET LAUNCH with a FLIGHT and K3 RELAUNCH) carries one line telling the CAPTAIN how to fly it. WAKE L and M: `SOLO (WAKE M): fly this FLIGHT as a solo CAPTAIN. Implement it yourself, with no CREW; …`. WAKE H and J, and multi-area FLIGHTs (two or more `Area` group labels, or two or more TYPE RATINGs other than DOCS): `CREW (…): you may split the implementation across your CREW COMPLEMENT.` This generalizes vocado's SOLO rule to every AIRPORT; DISPATCH still sends FLIGHTs in parallel. In a controlled study of one small task, a single session used the fewest tokens for the same accuracy.
  - Per-AIRPORT switch in the settings window, AUTOMATION → OPERATIONS → SOLO (`solo-default.json`, SUPERVISOR only): `on` or `off` (`off` = the FLIGHT PLAN as before). It ships `on` for every AIRPORT: the first server start after deploy writes `on` for every open AIRPORT and the deploy time once. A missing file reads `on`, a broken file `off`.
  - Misfire counters per AIRPORT for the last 7 days under the switch, against the 7 days before deploy: SOLO FLIGHTs that took CREW or were blocked for lack of one, SOLO FLIGHTs with block time above the same-WAKE median, and tokens per landed FLIGHT by WAKE. Shown only.
  - The Linear issue detail read now includes labels, so a FLIGHT missing from the snapshot still gets its WAKE.
