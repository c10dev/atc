### Changed
- SQUELCH ships on: every control role (TOWER, MCC, OCC, CROSSCHECK, REVIEW) runs `mode: on` with `fingerprint: v2` from the first start after deploy, so quiet ticks stop reaching the model. A missing `squelch.json`, or a role with no entry, reads `on` and `v2`; a file that cannot be parsed, or a value that is present but unknown, still reads `shadow` and `v1` so a tick runs. The server rewrites the live file to `on` and `v2` for every role once at that first start and records `migrated: "ATC-553"` with the time and the old values; after that only the SUPERVISOR's SQUELCH switch changes it. The off button writes `shadow` and `v1` explicitly. See [docs/squelch.md](docs/squelch.md) "Ships on as built (ATC-553)".
- MCC, CROSSCHECK and REVIEW run `atcctl tick <role>` as the first step of `/tick` (as TOWER and OCC already do) and stop at the LOG on `TICK QUIET`. Their Bash guard allows that one read command for its own role only.

### Added
- SQUELCH misfire panel: `GET /api/squelch/opens` gains `roles.<role>.live` (`dropped`, `disagreed`, `wrongSkips`, `idle`, `unknown`, `since`) and the settings window shows it per role for the last 7 days under the switch. It is a spot-check and gates nothing.
