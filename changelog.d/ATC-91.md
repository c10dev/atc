### Added
- RESTARTING (ATC-91, [docs/fleet.md](docs/fleet.md) 8.5 "RESTARTING as built"). A desktop `/clear` ends the session and the next one gets a new id under the same name. For up to `restartGraceMin` (default 30, `dispatch.json`) after a normal end, with no session file and no live session of that REGISTRATION, the AIRCRAFT is `RESTARTING` instead of absent: the FLEET list shows the status and `세션 없음 — /clear 뒤 첫 메시지 대기`, the card says how long it waits, and FLEET PLAN no longer proposes a LAUNCH for it. Found from transcripts and session files only, so nothing was added to `hooks/`.

### Changed
- DISPATCH keys proposals on the REGISTRATION (ATC-91, [docs/dispatch.md](docs/dispatch.md) 6.4), so a `/clear` no longer loses the AIRCRAFT. New ASSIGN proposals store `registration` (ATC-67 `registrationOf`) next to `aircraft` and `aircraftName`; the pair rule (24-hour `wrong-aircraft` and the rest), the AIRCRAFT reservation, `stillValid` and READBACK bookkeeping use it. Old lines without it read through `aircraftName`. send-guard is unchanged.
- A `proposed` or `approved` ASSIGN whose AIRCRAFT is `RESTARTING` waits instead of being SUPERSEDED for `AIRCRAFT 불가: 세션 없음`; after the grace it closes as before. `POST /api/dispatch/proposals/:id/release` answers 409 while the AIRCRAFT has no live session and is `RESTARTING`. The brief adds `waiting`, and DISPATCH cards and in-flight rows say the proposal waits for the first message.
