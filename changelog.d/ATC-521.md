### Changed
- CONTROL STOP, CONTROL RECYCLE and APPLY NOW record a control session as stopped only when its job's `state.json` reads `stopped` within about 20 s of `claude stop` exiting 0 (ATC-521, [docs/control-recycle.md](docs/control-recycle.md) 5). Before, exit code 0 was enough, and MCC job 4d8c68ae kept running next to its replacement after a RECYCLE recorded `ok: true`. A STOP that is not verified is `ok: false` with its own reason and a WARNING, and RECYCLE launches no replacement. A second WARNING fires when two live jobs carry the same control name (STALE ghost rows are not counted).
- One switch, CONTROL STOP CHECK (default on, SUPERVISOR only, settings window, OPERATIONS), turns both checks off. Its block shows the misfire counter: blocked STOPs, duplicate warnings, and how many the SUPERVISOR marked as false alarms or the check later contradicted. Every decision is a FLIGHT RECORDER line. The switch declaration lives in `server/switches/`, so this change is tier `user`.
